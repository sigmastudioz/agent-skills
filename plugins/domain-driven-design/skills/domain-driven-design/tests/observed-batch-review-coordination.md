# Observed case: coordinating artifact reviews and replacement publication

Recorded 2026-11-12 from a real multi-stage catalog session. This is a sanitized account of observed
coordination failures and recoveries, not a controlled evaluation or proof of universal efficacy.
Project assets, merchant records, credentials, personal paths and raw provider transcripts remain
with their owner and are not distributed here.

## Setup

The user authorized external agents to inspect source and candidate assets, a coordinator to
publish passing replacements, and removal of old display references only after consumer verification.
Reviewers received isolated creative-only packets. The coordinator retained the authoritative queue,
mutation access, exact-export release and live verification. Parallel review capacity was bounded.

## Observations

| Observation | Consequence and recovery |
| --- | --- |
| A copied review brief named the previous identity reference and garment in some fields, while its actual inputs belonged to the next item. | The mismatch was corrected before either provider launched. Packet fields and roles need a semantic preflight, not just a schema check. |
| A source/display review returned PASS without reviewing a newly generated output. | The source advisory remained separate from output acceptance and publication authority. Useful original evidence did not establish finished customer display. |
| One reviewer held a garment trim mismatch while another passed it. | The coordinator inspected originals and native candidate detail, then made one bounded correction. A separate numerical length estimate across differently posed bodies remained unverified; it was not reported as measured fit. |
| The owner rejected the supporting outfit while a product-fidelity correction was already running. | The in-flight result remained unpublished. A separately recorded owner-requested styling edit preserved product construction, and the new exact export received fresh reviews before release. Previous attempts were retained in the cumulative count. |
| A reviewer described two source views in one report row. | Its inspected-file set still matched both supplied inputs. Coverage was counted from the packet and inspected identities, not the number of descriptive rows; no paid review was replayed. |
| WebP inputs were supplied to reviewers as decoded PNGs. | Source and supplied hashes differed as expected. Dimensions and decoded RGBA equality established the scoped bridge; neither a filename match nor an unequal container hash would have established it. |
| Native save, variant bindings, live desktop/mobile framing and actual card hover were separately checked. | Old matched display references were detached only after the replacement was visible and correct. Original files and distinct unrefreshed coverage were retained. A count of photographs was not a count of completed products. |

## Resulting guidance and limits

See [multi-stage batches](../references/handoffs.md#multi-stage-batches-and-changing-instructions)
and [shell-started workers](../references/handoffs.md#workers-started-from-a-shell).
The transferable controls concern input roles, stage-specific evidence, bounded scheduling,
changed requirements and coordinated writes. The project's models, styling preferences, image-call
limits and publication sequence are local decisions, not global engineering requirements.

Existing helper/package checks do not establish that a future model follows this prose. No new
native-agent pressure test, unattended publishing system, provider-speed comparison or automatic
permission enforcement is claimed by this case.
