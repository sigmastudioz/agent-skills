# Maintained coding and comparison setup: frozen total task time trial

## Question and intervention

The user requested harder real coding work through Cursor, with models constructing the
comparison themselves and all setup time counted. Previous runner-only tasks supplied the
alternatives, cases and manifest; they could not establish end-to-end coding utility.

Two isolated tickets begin with exact maintained repository source, provenance and original
public contracts. These are real code excerpts with newly authored scaling tickets, not
production traffic or independently selected customer issues. Neither task supplies a candidate,
benchmark generator, workload data, adapter, expected-result file or manifest. Workers must
implement, build and execute their own comparisons. An unchanged reference supplies the original
behavior; it is not a coordinator implementation of the requested optimization.

Control receives normal Python standard-library tools and shared engineering defaults. Treatment
also receives the unchanged Tony 2.1 runtime skill, supporting references and actual runner/worker
scripts. No evaluation materials, previous results or task-specific solution are supplied. The
treatment is therefore the skill plus its tool, not the runner alone. Model choice is fixed to
`grok-4.7-high` in both conditions, preserving the last pilot's setting. Previous missing Fable
cells stay pending; no new Fable calls or account changes are part of this four-cell trial.

## Tasks and completion gates

1. Catalog: bounded-memory full-content release hashing, excluded-subtree pruning, compatible
   marketplace/render/build/check/CLI behavior and distribution symlink validation. A 48 MiB
   asset must render below 8 MiB peak Python traced allocation across import plus call.
2. Sequencing: exact deterministic greedy sequence optimization and efficient editorial validation.
   Preserve complete output, two-decimal ties, source order, blocks/pins, nonfinite values,
   nonmutation and supported error precedence. Coordinator check requires >=3x speedup at 1000
   tracks against the original, using alternating untraced calls; validation must avoid an unused
   proposal. These implementation timings are quality gates, not the measured agent time gain.

Supplied public tests and independent randomized/adversarial checks must pass. The independent
checker stays outside worker inputs and is frozen before dispatch. No post-result correction
call or reinterpretation of a failure is permitted. Coordinator source/tool audit must also
establish real integration, excluded-subtree pruning and preserved validation ownership; a test
that observes only the main happy path does not establish those properties.

Manual measurement audit (all required in both conditions):

1. Worker authored deterministic representative workload setup, adapters and expected-result
   generation. Catalog has many-small-files/ignored-tree and 48 MiB cases; sequence has >=300
   tracks in each of unconstrained and block/pin cases. Comparison exercises actual public code.
2. Every measured output is checked in full against the unchanged reference. Meaningful separate
   correctness/failure regressions cover public consumers. A correct output digest must originate
   from actual full-output equivalence or a canonical full-output digest, not selected fields.
3. At least three fresh-process untraced import/setup-plus-call timing samples and three distinct
   fresh-process traced allocation samples per implementation/workload. Allocation starts before
   source-module import and ends after the call. A demonstrated over-cap implementation may stop
   allocation sampling early. Workload generation is outside the runtime interval; its authoring
   and execution time remain inside the total agent task clock. Record raw samples/environment,
   apply resource exclusion honestly, and state filesystem/cache/RSS/statistical limitations.
4. Record pre/post SHA256 identities of original/candidate, adapters, generator, declared helpers
   and workload data (a deterministic manifest over generated files is acceptable). Source and
   workload changes during a final comparison invalidate it. Inspect actual successful tool
   receipts, process modes, source and numeric aggregates; a report-shaped JSON alone is insufficient.
5. Supplied readonly inputs/assets remain unchanged; additions and edits stay within the ticket's
   owned checkout. No outside/global skill reads, hidden checker reads, network, installs, extra
   agents, spending changes, commits or publication. Own scratch data and generated tool outputs
   are allowed. Missing proof, invalid measurements or incomplete integration cannot count as a
   successful fast task even if the agent process completes or proposes the right idea.

All automated and manual requirements are conjunctive. Report implementation acceptance,
comparison validity and process completion separately, including useful partial outcomes. Do not
force adoption of an inferior candidate; an honest rejection is not implementation completion.

## Dispatch and time accounting

Four fresh Cursor processes, two tasks x two conditions; one process/attempt per cell, maximum
one active, 1800 seconds each. Fresh independent Git clones share the task's committed source,
README, reference, tests and defaults. Condition order is counterbalanced: sequencing treatment
first and catalog control first, with deterministic pair shuffle. No cross-session reusable
control harness, shared model context, feedback or task correction. Cursor sandboxing and safe-tool
auto-review stay enabled, with no permission bypass. A blocked tool/account outcome stays blocked.

Primary clock is monotonic elapsed from immediately before Cursor process launch until it exits
or hits its deadline. It includes startup/service delays, reading instructions, planning, coding,
adapters, case/expected generation, manifest creation, all benchmarks, debugging/reruns, verification
and final reporting. It excludes queue waiting, coordinator preparation and post-task adjudication.
Timers are coordinator-observed, not worker estimates. A timeout is censored at the cap; an invalid
or unfinished task is not compared as a faster success. All internal failed attempts count.

Also record the coordinator's persisted preparation span from first task-packet creation to frozen dispatch,
total campaign wall time, and post-dispatch adjudication span as evaluation overhead. These are
shared experiment-design costs, not ordinary per-task skill setup, and cannot be attributed as a
condition difference. Generic skill development/build costs from the earlier trial are not charged
again as a new per-task setup, and this pilot still cannot establish amortized net development ROI.
Initial inspection before the first persisted packet was not timed and must remain explicitly
unmeasured; do not present the persisted span as complete experiment-design labor.
Break down worker stages only when actual tool/milestone timestamps support them; do not invent
precise stage labor from overlapping or unlabeled events. Report raw provider counters without
converting them to money or equating event counts/lines with quality.

## Interpretation and preservation

Freeze runtime, source tasks, protocol, checker, profiles and prompts before model work. Record
source origins and all input identities. Keep failed attempts, stale intermediate reports and
infrastructure errors; no post-score skill tuning or paid reruns. Normal tools means the common
standard-library environment, not every possible installed benchmark product.

Two tasks and one agent sample per condition do not establish statistical significance, a general
coding advantage or cross-model efficacy. Fresh isolated controls may overstate gains relative to
an engineer/model with an existing reusable harness. Full-skill treatment cannot isolate which
instruction or tool caused a difference. The coordinator authored the tasks and audits both
conditions; scoring is reproducible but not independently blinded. No novelty or prose bonus.

The plugin owns the profile, fixtures, frozen checks and results. Existing run_tools owns process
launch, capped attempts, isolation and snapshots; only profile-selectable timeout is added, with
legacy 1200-second behavior retained. The existing gap ledger owns traces and current state.
Retain exact prompts, source/output artifacts, raw counters and tool-only receipts in one durable
audit bundle, excluding private account data and model thinking. Include checksums, restore
instructions and a fresh-directory restore check. Preserve all earlier evidence and unrelated
working changes. Retain until superseded by reviewed evidence with no active consumer of originals.
