# Where engineering invention belongs

Select this skill for a consequential constraint or an explicit request to rethink a mechanism.
A product concept may need a new interaction or source of value. A scale problem may need a different
representation. An integration may become simpler by using authority already present elsewhere.
Architecture work may need to eliminate a boundary or intermediate operation. Investigate the actual
constraint before choosing among these moves.

Routine implementation, straightforward bugs, ordinary reviews and release checks use their existing
engineering workflows. If explicitly invoked on such work, take the simple route and explain when no
new mechanism is warranted. Do not manufacture an invention phase.

Available domain, UI, performance or platform specialists can supply necessary constraints and ordinary
execution discipline. They are optional; this skill adds no dependency or delegation authority. Keep one
owner for source and evidence. Load only the guidance that changes the current decision.
