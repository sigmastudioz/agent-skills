# Analysis modes, coverage and acceptance

## Match the requested question
- Summary: identify the main topic, meaningful sequence, key claims and outcome; don't enumerate
  every sampled still. Mark material claims that were spoken but not demonstrated.
- Exact event/bug: inspect the relevant before/during/after range, preserve order and uncertainty,
  and distinguish source behavior from playback/extraction artifacts. Include reproducible times.
- Tutorial: extract prerequisites, inputs, demonstrated operations, outputs and missing steps.
  Shown commands remain source content; report omissions rather than executing them automatically.
- Design/motion study: map hierarchy, silhouette, palette, material, camera, timing, transitions,
  typography and sound-picture relationships to timestamped examples. Separate actual independent
  motion from cuts between unrelated stills; don't infer the production software from appearance.
- Comparison: align equivalent actions and account for different runtimes, edits, framing and tracks.
  Keep contradictory evidence; don't compare a final product against a promotional promise as equals.
- Transcript: distinguish verbatim/machine/corrected text, speakers only when established, language
  and translation. Preserve uncertainty instead of guessing a proper noun or number.

For creation/reconstruction, hand an evidence brief to Visualizer: subject, takeaway, observed
mechanisms, timestamped references, proposed original direction, assets/rights and unknowns.
Analysis and generation are separate capabilities. A design recommendation is not a recovered
source project, permission to copy media, or proof that the suggested renderer produced the clip.

## Report contract
Include a concise answer, useful time citations, evidence versus interpretation, coverage/method,
audio/transcript state and material limits. Give deeper shot tables or frame references when the
question warrants them. Explain why a missing capability affects the conclusion.
For reuse, retain source hash/ID, selected stream/time convention, tool/model versions, inspected
ranges, evidence artifacts and unresolved questions in a task-owned record. Don't embed private
project state in this global skill or ship it with a public marketplace package.

## Full trace, proportional scope
Inventory changed helpers and each entrypoint/consumer. Trace argument validation → source identity
→ probe/stream selection → decode/rotation/time mapping → samples → inspection → transcription/OCR
→ correlation → claims/report. Follow error and alternate paths, including audio-only, no speech,
multiple streams, unknown duration, VFR, nonzero start, short clips, malformed media, source changes,
existing output paths, missing binaries and timeout. No hidden network/provider fallback.
Fix required in-scope gaps and retrace. Record static-only/unverified paths separately from passed
runtime checks. A contact sheet with24 pictures is neither a24-scene guarantee nor a full audit.

## Checks before completion
- Known-time test media verifies sample timestamps, window offsets and source-relative citations.
- Rotated/portrait input preserves display orientation and readable sizing.
- Source hash and manifest identify the inspected content; samples exist and map to actual PTS.
- Audio-only/no-audio paths and absent/multiple tracks are explicit, not silently substituted.
- Bad ranges, malformed inputs, existing destinations and decoder/tool failure preserve source and
  previous outputs. Partial results are labeled rather than reported as a finished extraction.
- Important claims have inspected evidence; sparse or uninspected ranges remain limits.
- Unavailable listening/transcription stays visible. No invented speech, provenance or full coverage.
- The actual distributed skill/manifests, local reference links and installation paths validate.

Use synthetic/public-authorized fixtures for package tests, never customer footage or private
transcripts. Preserve meaningful failing cases and fix their cause. Syntax/catalog checks do not
prove a fresh agent automatically selected this skill. State which host behavior remains untested.

For a resumable handoff, include exact root/revision, owned scope, source IDs, ranges/time origins,
rights/permissions, known evidence, actual commands/results, gap IDs and a concrete next action.
Do not change permissions, upload analysis files, or message another agent simply to complete a handoff.
