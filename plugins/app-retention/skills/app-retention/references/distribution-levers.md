# Free distribution levers for apps

Getting found is upstream of retention. These levers come from a solo developer's public
breakdowns (claims of 20,000+ monthly downloads without paid marketing; unverified). Each is free
to try and measurable; check current store rules before relying on one.

| Lever | What to do | Check |
| --- | --- | --- |
| Store name as a search term | Put the searched phrase in the title or subtitle ("Blackjack Trainer – Lumora"); use the subtitle, description and screenshot text for the same terms. Keyword tools (Astro, AppTweak) show demand and competition | Impressions and installs from search per term |
| Localisation per store | Each country store reads its own name, subtitle and keywords. Find terms that are popular but empty in a country (Apple Search Ads shows popularity without running ads) and localise the listing, even if the app stays in one language | Installs per storefront |
| Problem pages on the web | One working page per problem the app solves (a rent-splitting calculator for a bill-splitting app), each leading to the app. Google Keyword Planner shows search volume without running ads | Organic visits and app clicks per page |
| AI-answer visibility (GEO) | List the app on comparison and alternatives sites that AI assistants read (AlternativeTo, SaaSHub); describe it plainly next to the apps it replaces | Referrals from those sites and from assistant answers |
| Instant links | App Clips (iOS) or Instant Apps (Android) open one working part of the app from a link (one recipe, one workout); the same link opens the full app if installed | Clip opens to installs |
| Free-for-a-day listings | Make a paid app free briefly on deal communities (AppRaven) to close the ratings gap; the reviews must stay ungated | Rating count before/after, upgrade conversion of that cohort |
| App bundles | Offer a polished app to subscription bundles (Setapp and similar) that lack one like it; keep selling it directly too | Bundle revenue share |
| Over-the-air fixes | Ship bug fixes without waiting for review (within store rules: fixes and improvements only, not a different app) | Time from bug report to fix on devices |

Related build hygiene from the same source: subscribe to backend changes instead of polling every
few seconds, and tell coding agents not to keep fallback "v2 beside v1" copies of code that nobody
uses.
