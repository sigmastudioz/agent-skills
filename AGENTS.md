# Publication continuity

Before publishing, updating marketplace submissions or checking their status, read
[PUBLISHING.md](PUBLISHING.md). Its opening section maps approved destinations and current
coverage; dated historical sections do not override the latest map or private receipt.

Use `catalog.json` for the approved public set. Preserve full package functionality, existing
submission identities, old releases and sent-once actions. Keep exact account/case data and private
correspondence in the publisher's private handoff/receipt tracker, outside Git. Read actual provider
state and observation times; source publication is not native approval. Do not publish held-back
local work merely because it exists on the machine.
