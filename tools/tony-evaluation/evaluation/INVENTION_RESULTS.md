# Engineering invention 2.0: trial record

The [frozen protocol](INVENTION_PROTOCOL.md) defines this fresh comparison. The old
[1.1 pilot](RESULTS.md) and [1.2 coding trial](TOOLS_RESULTS.md) remain unchanged.
This report will distinguish blocked infrastructure, partial artifacts and completed solutions.

## What was rebuilt

Version 2.0 narrows the skill to engineering invention: make a consequential outcome possible by
changing the mechanism responsible for the constraint. Routine coding uses the existing workflow.
The six capabilities remain, with each supporting an invention rather than imposing a six-stage audit.
The central intervention asks for the decisive working slice early and for further analysis to answer
a new implementation or mechanism decision. It permits the conventional solution to win.

The selected treatment is the actual new SKILL.md plus references/invention-methods.md: 8,170 bytes,
concatenated with two newlines. It covers structural escapes and falsifiable proof without naming
these fixtures, supplying their algorithms, or adding an alternatives/report quota. Other references,
templates and tests are absent from worker inputs. The treatment was frozen before dispatch.

## Fresh task design and calibration

- **Maintenance Window Planner:** exact earliest pair conflicts for finite integer-time recurrences,
  up to a trillion windows per schedule, with public planner and JSON CLI. Expanding occurrence lists
  cannot meet the target. Different exact approaches are allowed.
- **Pulse Telemetry Analyzer:** exact chronological metrics and the first eight samples of nested
  compressed streams, including trillion-fold repetitions, with report and JSON CLI. The core and
  its consumer must both avoid expansion; approximation does not meet the documented contract.

Both initial public suites pass 3/3 small-input checks. The frozen held-out suites have 13 distinct
methods each; original implementations pass only 5/13 Windows and 6/13 Pulse. Coordinator-owned
witness implementations outside every worker input pass 13/13 on each. Windows' arithmetic oracle
is cross-checked against a small random brute-force oracle; Pulse checks small expanded sequences
and known large identities. These are feasibility checks, not independent task design.

Here, a breakthrough means overcoming a documented structural limit; an accepted solution may use
a well-known algorithm. These two algorithmic/representation tasks do not measure original research,
product imagination, hardware invention or every use of the six capabilities. Their shared expansion
bottleneck also limits diversity. They were chosen before dispatch and will not be replaced based
on which condition wins.

Cases use a local five-second guard. Pulse also checks less than eight MiB of traced allocation on
an encoded four-million-sample workload. These are local resource gates, not general throughput or
production-memory guarantees. No score rewards novelty, a named algorithm or matching prose.

## What the actual mechanisms show

**Windows control** replaces occurrence expansion with bounded offsets and congruence classes of
occurrence indices. Each feasible class is advanced directly into finite/query bounds. It touches
only engine.py and adds a regression file; the supported planner/CLI consumes the repaired engine.
It has 13 tool starts, including only one shell call for the baseline. It did not execute its new
regressions or a post-change CLI check before the deadline; coordinator checks establish the passing
final code separately.

**Windows guided** represents covered ticks as bounded residue pairs, solves their congruences,
and selects the earliest solution inside counted/query spans. It has 21 tool starts, including eight
shell calls. It tests prototypes against brute force, runs its post-change suite, and exercises large
counts and planner shapes before the bound. It read the selected guide once. The code is shorter and
more local verification was actually performed, but those observations are descriptive and do not
change the primary tie or supply a causal efficacy claim.

**Pulse control** computes fixed-size chronological segment summaries. Concatenation composes
extrema, endpoints, drawdown and leading/trailing increasing runs. A closed form handles repeated
segments, while a bounded preview and empty-body shortcut repair the terminal report path. This is
a working structural escape without added guidance. It has 18 tool starts and zero guide reads.
Its guided counterpart is unavailable, so no paired effect can be estimated for Pulse.

The controls therefore demonstrate mechanism invention under the common engineering defaults too.
The rewrite better matches the requested purpose, but the available sample does not establish added
performance. No runtime changes were made in response to these outcomes and no task was replaced.
